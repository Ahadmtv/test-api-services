# ADR 0001: یکپارچه ماژولار و قرارداد پایگاه داده

- وضعیت: پذیرفته‌شده برای طراحی MVP

## زمینه

سامانه هم‌زمان به قواعد رزرو، موجودی کیف پول، پرداخت و تسویه وابسته است. مرز سرویس خرد در این مرحله هزینه عملیات و هماهنگی تراکنش را زیاد می‌کند؛ consistency پایگاه داده در رزرو و پول اهمیت بالایی دارد.

## تصمیم

یکپارچه ماژولار با Go، یک نسخه پایدار واحد از Fiber v3 با نسخه دقیق قفل‌شده، PostgreSQL به‌عنوان منبع حقیقت، SQL صریح پارامتری از طریق `pgx/v5` و مهاجرت‌های SQL نسخه‌بندی‌شده به کار می‌رود. مرزهای `identity`, `providers`, `catalog`, `scheduling`, `booking`, `wallet`, `payments`, `settlement` و `audit` در `internal/` مالک قواعد و نوشتن داده خود هستند. API و worker می‌توانند نقطه ورودهای جدا ولی استقرار اولیه مشترک داشته باشند. ماژول دامنه به Fiber و ماژول دیگر به جدول‌های متعلق به ماژول مجاور وابسته نمی‌شود.

## پیامدها

- رزرو و ثبت مالی می‌توانند در تراکنش‌های PostgreSQL اتمی باشند.
- migrationها قرارداد بازسازی schema هستند؛ فایل اعمال‌شده اصلاح نمی‌شود.
- مرز ماژول باید با review و آزمون حفظ شود؛ استخراج سرویس در آینده به نیاز اثبات‌شده و ADR جداگانه وابسته است.
- نسخه دقیق Go/Fiber در راه‌اندازی تثبیت می‌شود؛ تغییر عمده Fiber نیازمند تغییر هماهنگ و ADR است.
- ORM اضافه نمی‌شود مگر با ADR مستند درباره سازگاری با SQL صریح و constraintهای پایگاه داده.
